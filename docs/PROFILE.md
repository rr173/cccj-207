# 限定 Profile 说明（Confined HL7 Profile）

本接收服务只实现本题限定的 HL7 子集。凡超出本表的内容**明确拒绝**，不做任何猜测式映射。

## 1. 传输层（MLLP）

- 帧格式：`VT <payload> FS CR`（`0x0B ... 0x1C 0x0D`）。
- TCP read 边界与帧边界无关：接收端按字节流增量组帧，支持半帧、跨片、单 read 多帧。
- 单帧字节数上限 `--max-frame`（默认 1 MiB）；超限帧报错并丢弃，解析器在下一个 `FS CR` 重新同步。
- 连接断开时未闭合的帧被丢弃并记录，绝不拼接到下一条连接。
- 帧级错误（VT 前垃圾字节、FS 后非 CR、超限、断连残留）以 `(conn_id, 流内绝对偏移)` 定位，写入 `frame_errors` 诊断表；连接继续处理后续完整帧。损坏帧**不会**伪造出任何已确认业务消息。

## 2. 消息与版本

- 消息类型：仅 `ORU^R01`（MSH-9 前两个组件）。
- Profile 版本：仅 `2.3.1` 与 `2.5.1`（MSH-12）。其余版本明确拒绝（AE）。
- 字符集：帧载荷必须可解码为 UTF-8；段终止符为 `CR`，允许 `CR LF`。
- 字段分隔符与编码字符从 MSH-1/MSH-2 读取，不假设 `|` 与 `^~\&`。
- 转义序列：`\F\ \S\ \R\ \E\ \T\` 还原为对应分隔符；`\Xhh..\` 按十六进制解码（UTF-8）；`\H\ \N\` 为显示开关，不产出文本；`\Z...\` 本地转义保留内容原文；未知或未闭合序列按字面保留。
- 空字段（存在但为空串）与缺失字段（段提前结束）严格区分：库内分别为 `''` 与 `NULL`。

## 3. 段布局

```
MSH                 恰好 1 个，必须为首段
PID                 恰好 1 个，紧随 MSH
PV1                 恰好 1 个，紧随 PID
  以下为一个或多个 OBR 组：
  [ORC]             每组 0..1，位于 OBR 之前
  OBR               每组 1 个
  NTE* / OBX*       OBR 之后、首个 OBX 之前的 NTE 属于该 OBR；
                    OBX 之后的 NTE 属于该 OBX
```

- 不在本表的段（如 IN1、MSH 重复出现）→ 拒绝。
- OBX 出现在任何 OBR 之前、NTE 归属不明 → 拒绝（"OBR/OBX 归属不明"）。
- 组内允许 0 个 OBX（该组不产生结果行）。

## 4. 字段表（可空性即校验规则）

### MSH
| 字段 | 含义 | 可空 |
|---|---|---|
| MSH-3 | sending application（发送方身份一部分） | 必填 |
| MSH-4 | sending facility（发送方身份一部分） | 必填 |
| MSH-7 | 消息时间（原文保存） | 可选 |
| MSH-9 | 消息类型，必须 `ORU^R01` | 必填 |
| MSH-10 | 消息控制 ID（传输去重键） | 必填 |
| MSH-11 | processing id | 可选 |
| MSH-12 | 版本，必须 ∈ {2.3.1, 2.5.1} | 必填 |

### PID
| 字段 | 含义 | 可空 |
|---|---|---|
| PID-3 | 患者标识列表（CX，可重复）。每重复项 CX.1 identifier 与 CX.4 assigning authority 均必填。患者键 = (assigning authority, identifier)，不按显示值合并 | 必填 |
| PID-5 | 患者姓名 | 可选 |

### PV1
| 字段 | 含义 | 可空 |
|---|---|---|
| PV1-2 | patient class | 可选 |
| PV1-19 | 就诊号（CX，取 CX.1） | 可选 |

### ORC
| 字段 | 含义 | 可空 |
|---|---|---|
| ORC-2 | placer order（EI，取 EI.1；OBR-2 为空时回退使用） | 可选 |
| ORC-3 | filler order（EI，取 EI.1；OBR-3 为空时回退使用） | 可选 |

### OBR
| 字段 | 含义 | 可空 |
|---|---|---|
| OBR-2 | placer order（EI.1） | 可选 |
| OBR-3 | filler order（EI.1） | 可选 |
| OBR-4 | 检验项目（CE：代码、名称、代码系统；代码与代码系统必填） | 必填 |
| OBR-7 | 观察时间（OBX-14 缺失时的回退） | 可选 |
| OBR-22 | 报告时间（结果行的 reported_at） | 可选 |

### OBX
| 字段 | 含义 | 可空 |
|---|---|---|
| OBX-2 | 值类型。2.3.1：NM,ST,TX,FT,CE,DT,TM,TS；2.5.1 另增 CWE,CNE | 必填 |
| OBX-3 | 观察标识（CE：代码、名称、代码系统；代码与代码系统必填） | 必填 |
| OBX-4 | 子 ID | 可选 |
| OBX-5 | 结果值（按 OBX-2 保留类型；**数值字符串不转浮点**；层次以声明分隔符重 join，叶子已反转义） | 必填 |
| OBX-6 | 单位（原文） | 可选 |
| OBX-7 | 参考区间（原文） | 可选 |
| OBX-8 | 异常标志（原文） | 可选 |
| OBX-11 | 结果状态，须 ∈ HL7 表 0085（C D F I N O P R S U W X） | 必填 |
| OBX-14 | 观察时间 | 可选 |

### NTE
| 字段 | 含义 | 可空 |
|---|---|---|
| NTE-3 | 注释文本（可重复，重复项以重复分隔符 join） | 必填 |

## 5. 消息身份与去重

- 传输去重键 = (发送方, MSH-10)，发送方 = `MSH-3^MSH-4` 原文。
- 相同键 + 相同原始字节 → 重送：不新增消息或结果行，返回 AA。
- 相同键 + 不同字节 → 身份冲突：拒绝（AE），保存有界诊断与原始证据，**不覆盖**旧消息。
- 业务字段（患者、订单、检验代码）不能代替消息身份：不同控制 ID 的消息可合法携带相同患者/订单。

## 6. 消息内重复结果键

结果键 = (filler order, placer order, OBR-4 代码+系统, OBX-3 代码+系统, OBX-4 子 ID)。
同一消息内键重复时：载荷（值、类型、单位、区间、标志、状态、时间、NTE）与来源语义完全一致 → 合并（保留首次出现的来源坐标，`merged` 计数）；否则整条消息拒绝，不产生任何结果行。

## 7. 提交 / ACK 衔接

- 消息身份、原始字节、全部结果行、成功状态在**单个 SQLite 事务**内落定（WAL + `synchronous=FULL`）后才发送 AA。
- 提交失败或服务在提交边界退出 → 不发成功 ACK；客户端重送时按已提交消息身份判定，不重复插入。
- 持久 inbox 记录每次处理尝试（received → committed → acked / duplicate / rejected / conflict）。重启恢复时：`received` → `recovered_incomplete`（未完成的恢复项）；`committed` 未 `acked` → `ack_lost`。
- 诊断与证据有界：detail ≤ 1000 字符，evidence ≤ 8192 字节（截断）。

## 8. 确定性故障注入点

`--fault-inject point:action:n`（n 为第几次命中触发）：

| 注入点 | 位置 |
|---|---|
| `after_frame` | 收完整帧后 |
| `during_parse` | 解析中（MSH 校验通过后） |
| `before_commit` | 提交事务开启前 |
| `after_commit_before_ack` | 提交成功后、ACK 发送前 |
| `after_ack` | ACK 已发送后 |

action：`exit`（`os._exit(70)` 模拟崩溃）或 `raise`（模拟内部失败，连接继续）。
